# Agent Note: 会话行【接力】：先派发、再打开、后归档

Status: implemented

[English](2026-11-06-session-relay-button.md) | 中文

## 问题

接力纪律（P1 300k 止损 / P2 闲置唤醒）要求操作者依次手过三个面：save 出旧会话、派发携带种子的新会话、再归档旧行——而三者之间的缝恰是陈旧上下文滑入的地方：最后一次 DONE save 之后仍可能落新消息，抢跑 save 的接力会继承未保存或未完成的工作。会话行悬停已有归档、置顶，但行上没有任何动作能表达「把这份工作换个会话继续」的一键意图；而任何把 save 放进点击同步路径的编排，都会让按钮以 save 的速度而不是界面的速度作答。

## 决策

接力按钮是两次服务端调用之上的薄编排器，save 永不进点击路径（方向 7）。一次点击按序跑链：`POST /api/session-dispatch`——携带所属 Workspace（从 workspace 快照查得）、含源会话 id 的本地化种子、源会话显示标题（让续接者沿用名字），以及 2026-11-04 派发裁定要求的显式 `danger-full-access` 钉；拿到 200 之后才本地坐入新会话（与 `createNamed` 同款跨传输 seat）、打开为主视图，然后才走既有封印门归档流归档源会话（安静绿灯配撤销通知、陈旧一行提示、红灯确认——全部原样复用）。先建新、后归档、只向前：派发失败什么都不归档，抛可重试的 `relayFailed` 通知并带上服务端原话；继任者已存在而归档失败抛 `relayArchiveFailed`，绝不回滚已建会话——行上保留普通归档入口供手动重试。按钮仅悬停：无菜单行，锁定范围。

显示门在这里是 fail-closed，与归档门的 fail-open 正好相反。按钮在真实行上恒显（非空白占位、非已归档、不缺 `workspace/archiveSession` 访问权），在行的 C1 封印判定恰为 `DONE` 且会话已停轮之前保持禁用、原因进 tooltip：归档门原谅封印服务不可达，因为它不创建任何东西；而派发绝不能抢跑 save，所以只有被证明的 DONE 才能接力——N_A/NEUTRAL/LEGACY 绿组在这里照样禁用。禁用态走 `aria-disabled` 加 `data-unavailable` 而非原生 `disabled` 属性，因为原生 disabled 按钮不再向 Tooltip 投递解释原因所需的 hover/focus 事件（`MessageIconActions` 不可用分支先例），原因行同时挂 tooltip 文案与 `aria-describedby` 视觉隐藏 span。派发在途时按钮显示进行中原因且不可二次触发；继任者一旦派出，行即用尽——按钮隐去，绝不再提供第二次接力。

## 考虑过的替代方案

**点击内等 save（save → 派发 → 归档一条同步流）。** 否决：按钮必须以服务端调用的速度作答，而 save 是慢且可中断的半边——把按钮扣在它上面，正是方向 7 裁定排除的原地转圈体验。

**未收口 DONE 的行直接隐藏按钮。** 决策否决：禁用按钮加 tooltip 说明原因（先 save、运行中、在途）会告诉操作者下一步做什么；看不见的动作不留任何能力存在的痕迹。

**沿用归档门的 fail-open 绿组（N_A/NEUTRAL/LEGACY 视为可接力）。** 否决：两门回答的问题不同。归档门原谅封印服务不可达，因为归档保住日志；派发创建活会话并排队 prompt，判定不是恰 DONE 就意味着种子可能与尾随闲聊抢跑。这个不对称是刻意的，写在两门的注释里。

**归档半边失败时回滚已建会话。** 否决：只向前。继任者已坐入、已打开、已下种子——为了列表整洁毁掉在产状态是错误的交换；`relayArchiveFailed` 点名缺失的半边，行上保留归档入口。

**补一条菜单行给触屏（slot 文档的 hoverless 指引）。** 缓办：锁定范围是先做悬停按钮；inject 面与链路对菜单已就绪，等触屏排期再挂。

**派发 title 沿用源会话 vs 新自动标题。** 沿用：续接是同一根工作线，源会话归档后退出默认列表，且派发路由上不存在自动标题机制——一个字段把两半都认得出。

## 后果

行内动作条现在是接力、归档、置顶的顺序，按钮的三个禁用原因是八语言字典里的定型文案（种子 prompt 同样入典，因为它是用户可见的对话文本）。派发客户端把等待封顶十五秒，卡死的宿主不能把行永久扣在在途态；中止只取消等待、不取消请求，超时后才完成的服务端会留下一个可见的继任者，重试可能重复——可见、可归档，绝不藏。`archiveQuietly`/`archiveSealGated` 增加可选 `onHardFailure` 回调，让链路能学到归档半边在自家活干完之后死了；既有调用方不传参、行为分毫不变。apply 侧测试钉住链序（派发 body、seat、open、archive）与两枚失败通知；组件测试钉住恰 DONE 门、运行中与在途原因、用尽即隐。触屏与纯键盘用户在补菜单行之前拿不到接力。
