# Agent Note: 自动路由控制器——一个事实一个告警面

Status: implemented

[English](2026-11-04-auto-route-poll-alarm.md) | 中文

## 问题

用量控件的来源徽标在 `dsh-auto-route` 控制器轮询读数失败时渲染一个红色圆点、在默认源与在途源分叉（95–99 死区）时渲染一个警示圆点。两个圆点与进度条自身的预警颜色抢同一个扫视列的注意力；而一次瞬时网络抖动——实测约 90 秒、自愈——点亮圆点的声量和真故障一样大。同时，真正的可用性问题（控制器连续数分钟读不到读数）反而没有任何常驻告警面：侧边栏圆点是唯一信号，自愈即消失，且控制器的 warn 日志行在 web profile 里落不到任何持久文件。

## 决策

按持续时长分层，一个事实一个告警面（2026-11-04 裁定）。两个来源圆点全部退役：用量预警只由进度条颜色承载，来源状态由 Go 窗口行整体降透明度加按钮 tooltip 写明，分叉态不需要任何装饰。瞬态轮询失败只保留为按钮 `title` 上一行悬停可见的提示（`glance.source.pollError`）——不常显、不进环境层。持续失败（连续失败时长达约 5 分钟，45 秒节拍下 ≈ N=7）则让安康盾染红、队列告警行用专属文案插队，共享的健康明细增加第三段展示原始错误文本与连续时长。

持续判定搭现有健康帧的便车、不新增客户端请求：控制器每个 tick 结束后——成功或失败都写，因为沉默的写入端读作死循环——把 `{at, ok, 有界的 error, failingSince（本轮首个失败的时刻）}` 戳进 `<dsh-home>/auto-route-poll-state.json`。session-controller 的心跳扫描在读值守总账的同一处读这个文件，把一个可选 `autoRoute` 面折进同一个 `api-session/health` 帧；`sustained` 由折叠端而非写入端计算，告警阈值因此住在消费者旁边。缺省语义与值守总账的 fail-closed 刻意相反：值守采集器是必装件，本插件是可选件，所以文件缺失、解析失败或过期一律让该面「脱挂」，客户端渲染一行安静的「未接入」——不是坏、更不是误报红。版本错配向瞬态失败兜底：没有 `failingSince` 的旧写入端无法证明时长，就永远读作未达阈值，绝不闪盾。

## 考虑过的替代方案

**保留红点、另加盾告警。** 否决：一个事实两个面，等于给圆点叠上双重含义，正是退役要消除的稀释。

**用琥珀/暗底在同一徽标上编码「用量警告 + 轮询失败」。** 用户否决：一徽标双含义，UI 就说不清自己在报哪个事实。

**每次抖动都闪安康盾。** 以「狼来了」否决：亚分钟级连接重置一天能响十次，会把用户的警觉训练没。

**把 auto-route 的请求与 dsh-usage 合并。** 否决：两个消费方刻意隔离故障域；裁定维持双请求。

**由生产端在状态文件里直接写 `sustained`。** 否决：阈值是 UI 策略常数，放在折叠端计算让写入端保持纯事实记录员，判定还能随 15 秒扫描刷新，而不必等 45 秒的 tick。

**在 `sessionController` 上加推送 API。** 以 duty 文件式取代：文件解耦两个仓、是事故取证可直接查看的证据，且完全复用既有值守总账范式。

## 后果

控件静止时侧边栏逐字节回到徽标前布局，自愈的抖动在侧边栏不留痕迹——排查时钻取面（按钮 tooltip、盾明细）仍展示当前原始状态。队列告警新增一个分支，其文案永不借用「对账对不上」，因为账是平的、瞎的是控制器。状态文件带来每 ≤60 秒一次小写入和每 15 秒一次小读取，两端都是尽力而为：写入失败或文件缺席只降级为脱挂的面，绝不会变成误报。`meters.ts` 的错误串现在追加有界的 `error.cause` 链（三环、每环 160 字符、无密钥——bearer 键在请求头里），裸的 `fetch failed` 不再掩盖断点究竟在 DNS、代理还是 TCP。客户端改动随下次 bundle 构建加刷新生效；帧折叠与写入端要搭宿主和 web profile 下一次合并重启一起上——任何一侧先落地都各自优雅降级。
